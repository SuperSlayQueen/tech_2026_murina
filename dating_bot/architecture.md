# Этап 1: Планирование и проектирование Dating Bot

## 1. Описание сервисов

Система представляет собой dating-приложение на основе Telegram-бота.

### 1. Bot Service
Отвечает за взаимодействие с пользователем через Telegram:
- регистрация пользователя (/start)
- просмотр анкет
- лайки / пропуски
- запуск диалогов при совпадении

### 2. Backend (API)
Основная бизнес-логика приложения:
- обработка пользователей
- работа с анкетами (CRUD)
- обработка лайков и мэтчей
- расчёт рейтинга
- взаимодействие с БД, Redis и RabbitMQ
- отправка задач в Celery

### 3. Database (PostgreSQL)
Хранение всех данных:
- пользователи
- анкеты
- лайки
- мэтчи
- рейтинги

### 4. Redis (кэш)
Используется для:
- хранения предзагруженных анкет
- ускорения выдачи анкет пользователю
- хранения результатов задач Celery
- брокер сообщений для Celery (опционально)

### 5. RabbitMQ (Message Queue)
Очередь сообщений для асинхронной обработки событий:
- обработка лайков и мэтчей
- обновление рейтингов
- отправка уведомлений пользователям
- буферизация событий между сервисами

### 6. Celery (Task Queue)
Фоновая обработка отложенных задач:
- периодический пересчёт рейтингов (primary + behavior score)
- обработка событий из RabbitMQ
- очистка устаревших данных в Redis
- отправка отложенных уведомлений


## 2. Архитектура системы

Система построена по микросервисной архитектуре с очередью сообщений:

- Telegram пользователь взаимодействует с ботом
- Бот отправляет запросы в Backend
- Backend работает с БД и Redis
- События публикуются в RabbitMQ для асинхронной обработки
- Celery забирает задачи из RabbitMQ и выполняет фоновые вычисления

## 3. Схема данных (База данных)

### Таблица users
- id
- telegram_id
- created_at

### Таблица profiles
- id
- user_id
- name
- age
- gender
- city
- bio
- created_at

### Таблица likes
- id
- from_user_id
- to_user_id
- created_at

### Таблица matches
- id
- user1_id
- user2_id
- created_at

### Таблица ratings
- id
- user_id
- primary_score
- behavior_score
- total_score
- updated_at

### Таблица events (для RabbitMQ)
- id
- event_type (like, match, rating_update)
- payload (JSON)
- created_at
- processed (boolean)

### Таблица celery_taskmeta (автоматически создаётся Celery)
- task_id
- status
- result
- date_done
